# 绘域全量重构设计

## 目标

保留正式 API 地址和现有产品能力，将前端、后端、运行数据、部署入口分离。移除旧页面资源、兼容入口、旧浏览器缓存、旧工作流格式、重复模型目录和静默降级逻辑。

## 不变量

- 现有 `/api/v1/*` 地址与账户、积分、素材、任务、作品数据继续可用。
- 模型能力、参数与价格只由后端目录提供。
- 图片、视频、音频的提交入口统一为生成任务领域；每个操作仍有明确的请求契约。
- 无效输入返回明确错误，不转换旧格式，不自动改用其他模型。
- 运行数据不再和源码混放。

## 目标边界

前端采用原生 ES Modules：`frontend/js/core` 提供基础能力，`frontend/js/components` 提供通用组件，`frontend/js/features` 按生成、工作流、素材、发现、账户拆分。HTML 只装配页面，样式按 token、base、layout、component、feature、page 拆分。

后端最终位于 `backend/huiju/`，采用 FastAPI route → domain service → provider/repository 的单向依赖。`catalog` 是模型、能力、参数和价格唯一来源；`providers` 只处理第三方模型；`domains` 承担生成、工作流、素材、账户、积分等业务；`runtime` 只承担队列、转发和 GPU 调度；`edge` 只承担边缘代理与统计。

## 删除策略

完成相应替换和行为测试后删除根目录前端巨型文件、兼容启动文件、旧 CSS 覆盖层、旧工作流节点映射、旧 localStorage/URL 迁移及 JSON/SQLite 双写读取。生产用户数据迁入唯一存储后再删除旧数据读取代码。

## 验收

- `/api/v1/bootstrap` 提供前端所需的唯一模型目录。
- 文生图、图生图、文生视频、图生视频均可从同一工作台入口完成。
- 素材上传、任务查询、历史、工作流、账户和积分全量回归通过。
- 前端不含旧兼容状态和第二份模型能力目录。
- 服务由明确的 API 和 Edge 入口启动，源码目录不含运行时数据。
