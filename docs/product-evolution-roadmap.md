# 绘域产品演进路线图

## 基线

当前版本已经把快速创作和工作流统一在同一套媒体契约上：图片、视频、音频都从同一个素材输入区进入；工作流仅保存 v6 图结构和九种当前节点。下一阶段不再引入旧节点或旧数据格式兼容层。

## 工作流幕布

### 第一阶段：从“连线画布”变成“可控执行图”

1. 为每次运行生成只读运行快照，记录节点输入、输出、耗时、额度和错误原因。
2. 节点增加“单节点试跑、从此节点继续、缓存命中、失效原因”四个运行状态；成功节点可锁定，修改上游后仅使受影响的下游节点失效。
3. 运行前显示总额度、预计时长和外部模型清单，用户可选择完整运行或只运行选中分支。
4. 画布右侧固定运行检查器：按拓扑顺序展示队列、实时日志、媒体预览和可复制的失败原因。

验收标准：一个含图像、视频、音频的 DAG 可以断点重跑；未受影响的节点不重复计费。

### 第二阶段：从节点集合变成可复用创作资产

1. 增加分组、注释、命名输入/输出和折叠子流程；子流程只通过显式端口交换媒体。
2. 把已验证流程发布为模板，模板包含参数面板、示例素材、模型约束和预估成本。
3. 引入版本对比：同一工作流可以比较两次运行的节点参数、媒体结果、耗时和成本。
4. 分享只发布模板定义和作者明确选择的示例资产；运行结果默认保持私有。

验收标准：创作者能把“商品主视觉”“角色设定到动态镜头”等常用流程复用为一个参数化模板。

### 第三阶段：面向叙事生产的编排层

1. 提供“分镜、角色、场景、镜头、声音”五类领域节点，但底层仍编译为当前统一媒体节点，避免第二套执行引擎。
2. 支持批量变量和场景表：一个工作流可对多个角色、镜头或商品批量运行。
3. 为视频节点增加镜头连续性检查：引用同一角色/场景资产时，提示模型、参考图和尺寸的冲突。

验收标准：短剧项目可以从场景表生成可追溯的分镜资产，而不是散落的一组单次生成记录。

## 工作区

### 第一阶段：项目化工作台

1. 顶层对象从“当前页面”升级为“项目”；项目持有素材、工作流、生成记录、分镜和成员权限。
2. 主区采用稳定的三栏：左侧任务导航，中间创作/画布，右侧上下文检查器；底部保留可收起的结果货架。
3. 快速创作、工作流、资产库使用同一项目上下文；一次上传的素材可以直接成为画布输入，而不是重复上传。
4. 创建页签式工作区：同一项目可同时打开“快速创作”“镜头工作流”“资产库”，切换不丢失编辑状态。

验收标准：用户能够在一个项目中从提示词、参考素材到最终图片/视频/音频完整闭环。

### 第二阶段：从结果列表变成素材关系网

1. 资产库以“来源、依赖、角色/场景标签、版本、授权状态”组织媒体；每个结果可回溯至生成参数和工作流运行。
2. 结果货架支持并排比较、选为参考图、发送到工作流、设为场景/角色资产和批量归档。
3. 引入不可覆盖的版本链：编辑已有素材产生新版本，不修改原媒体。

验收标准：任意交付物能在两步内追溯来源，也能作为下一次创作的受控输入。

### 第三阶段：协作与交付

1. 项目角色采用所有者、编辑、评论者三档；评论只锚定到资产版本、画布节点或分镜卡片。
2. 提供审阅视图：以时间线展示每个镜头的画面、音频、备注、状态和导出规格。
3. 导出包以项目快照生成，包含成片、素材清单、授权记录和运行报告。

验收标准：一个小团队可在不共享 API Key、不暴露私有素材的情况下完成审阅和交付。

## 实施顺序

1. 先做工作流运行快照、节点缓存与运行检查器。
2. 同步引入项目实体和统一资产引用。
3. 再做子流程/模板与资产版本链。
4. 最后叠加分镜批处理、协作和导出包。

每一阶段都以现有 v6 图结构为唯一输入；有破坏性的数据模型升级时，采用一次性离线迁移，不在运行时代码中保留兼容分支。
