# 绘域产品、幕布与社区首轮全链路审计（2026-09-23）

## 范围与方法

- 对照即梦和小云雀的官方产品说明，重点考察“创作入口 → 资产/画布 → 运行结果 → 再编辑/分享”的连续性，而非照搬视觉样式。
- 在隔离数据目录启动本地服务，实际操作首页、桌面/手机宽度工作台、工作流幕布、发现/共绘广场、个人资料和额度页；未调用收费生成模型、真实支付和短信接口。
- 执行 `python -m pytest -q`：159 项通过；检查前端主要脚本语法通过。用本地服务复现工作流发布问题，并检查前后端数据契约。
- 此文档将“复现缺陷”和“规划能力缺口”分开。严重度：P0 为隐私/数据风险，P1 为核心路径受损或重要信息误导，P2 为明显体验摩擦，P3 为细节。

### 首批修复与剩余项

- F-01 已修复：公开工作流过滤素材 URL、资产 ID 和素材输入提示词，本机草稿不受影响；发布弹窗告知复用者须重新选择素材。
- F-02 已修复发布校验：后端拒绝断图、重复/非法边及环，前端给出连接提示；运行错误的细粒度反馈仍归 F-09。
- F-03 已修复：移除与实时价格冲突的静态扣费数值，价格页首屏明确支付尚未开放。
- F-04 已修复：静态样例显著标注“官方示例”，不再展示模拟点赞；真实用户投稿仍按社区数据展示。
- F-10 部分修复：中等屏宽下广场发布按钮不再被挤成竖排；跨创作模式的输入区一致性仍待处理。
- F-05 至 F-10 及后续结构性能力仍待实施。本轮修复后自动化测试为 161 项通过。

## 已知能力缺口（非本轮“新发现缺陷”）

`docs/product-evolution-roadmap.md` 已明确提出但尚未完成：运行快照和费用追踪、节点缓存/断点续跑、运行前总成本和时长、可检查的运行日志、分组/子流程/参数化模板、工作流版本对比、项目级上下文与共享资产关系、跨模式稳定工作区、协作与交付。它们解释了为何现有画布偏“连线工具”而非完整制作空间。优先实现顺序仍应以高危发布问题和基本可用性为先，再推进这些结构性能力。

## 竞品对照后的绘域设计原则

即梦的智能画布和小云雀的创作 Agent 画布都强调在同一空间中引用资产、继续生成与编辑；绘域应形成自己的“创作手稿”语言：浅纸色工作面、深绿操作层、暖金代表消耗/执行状态。每一层只承担一种职责：工作台承载意图与快速生成，幕布承载可追踪的媒体依赖，社区承载可复用的公开成果。重点不是增加入口，而是让结果进入资产、资产进入幕布、幕布生成可再编辑成果的回路清晰可见。

## 测试覆盖缺口与下一轮顺序

当前 159 项测试全部通过，但许多是源码结构契约或单接口断言，未覆盖跨页面真实操作。增加三类回归测试：

1. 发布契约：空图/断图拒绝发布；公开图不泄露私有媒体引用；公开作品的提示词选择与实际响应一致。
2. 关键旅程：输入提示词→生成记录→加入资产→放入工作流→运行→保存→发布→他人复用；图片和视频各跑一次。收费模型通过隔离/模拟提供者验证，不用真实额度。
3. 响应式/视觉：390px 和桌面尺寸分别检查首页、快速创作各模式、幕布、广场、弹窗；检验键盘操作与错误反馈。

本轮尚未声称验证真实模型质量、真实支付、短信注册、长视频导出或生产环境并发；这些需要沙箱凭据及对应测试环境，不能用当前 159 项通过替代。
